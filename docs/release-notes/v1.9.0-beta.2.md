# Crona v1.9.0-beta.2

Crona v1.9.0-beta.2 makes Pomodoro break deferral daemon-authoritative and advances the local IPC protocol to `1.3`.

## Highlights

- The daemon broadcasts a five-second break-deferral warning through the companion alert-delivery channel.
- Companion action acknowledgements allow the daemon to validate and apply the configured 30, 60, or 120-second deferral while owning the resulting work-to-break transition.
- Core setting mutations broadcast `settings.changed` so connected TUI and companion clients can reload shared state.
- Deferral state is persisted as a one-shot current-segment extension, preventing the next work segment from inheriting elapsed-time offsets.
- Missing companion acknowledgements fall back to the normal notification backend.
- The daemon records protected dates in canonical `awayDates` as they occur, so momentum and other historical calculations remain stable when rest rules change without treating future rules as history.
- Calendar surfaces render historical away dates in red, while date-specific Daily and Wellbeing views show a concise recovery message for those dates.
- The dashboard focus target is derived from estimates on issues due in the requested day or range and returns zero when no estimated work is due.
- Issue due-date calendars prevent selecting past dates or configured future rest dates, dim past dates, and mark rest dates in red.

## IPC changes

- Automatic deferral uses `timer.defer_break` instead of the previous `timer.extend_current_session` method.
- Each Pomodoro work segment accepts at most one break deferral, including requests made directly over IPC.
- Away history records the current day through the logical-day scheduler, avoiding premature wall-clock migration entries.
- Alert delivery acknowledgements may include `actionId`, `actionSeconds`, and the action’s `sessionId`.
- The daemon emits `timer.break_deferral_warning` before the work boundary and `timer.break_deferred` after applying the action.
- Clients should advertise/use protocol version `1.3` before depending on these fields and methods.
- `settings.away_mode` is the daemon-owned operation for changing live away mode; generic settings patches cannot modify `awayModeEnabled` or `awayDates`.

## Fixes

- Timer transitions are serialized across IPC requests and scheduled callbacks, so concurrent deferral requests cannot apply the extension twice.
- Rescheduling a boundary invalidates an already queued stale callback, preventing an acknowledged deferral from immediately starting the break.
- The issue pane now advertises the due-date action as `[d]`, matching the actual binding.

## Companion integration

The companion should acknowledge the warning action with its configured 30, 60, or 120-second preference when deferral is enabled. The daemon accepts only the action offered for that delivery and validates its duration. When disabled or declined, the companion should send an empty action acknowledgement; when no acknowledgement arrives, the daemon uses the normal notification fallback.
